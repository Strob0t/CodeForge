## R1 review: Go HTTP layer, wiring and config (snapshot 71bdf542)

I found 22 issues: 2 high, 10 medium and 10 low. Paths are relative to the snapshot. I did not re-report any open KI. Finding 17 shows that KI-104 understates one path.

### Findings

**1. HIGH · feature not wired (security control) · cmd/codeforge/main.go:1067, internal/adapter/http/routes.go:89-99, 858-860**
- **Defect:** `main.go` calls `MountRoutes` without `WithAuditStore`, so the audit log is off in production. Every `audit(...)` middleware passes requests through unchanged, and `GET /api/v1/audit-logs` is never mounted.
- **Scenario:**
  - An admin deletes a user or project, updates settings, rotates a webhook secret or assigns an MCP server, and no `audit_log` row is written.
  - `GET /audit-logs` answers 404.
  - `RecordAudit` finds no recorder and returns nil. The "fail closed" MCP assign/unassign and webhook audit that SECURITY.md:40,166,197 describes therefore never blocks anything.
  - The GDPR export's `audit_trail` is always empty.
- **Evidence:** `cfhttp.MountRoutes(api, handlers, cfhttp.WithAuthRateLimiter(authRL))`. The tests build routes with `WithAuditStore`, so CI stays green.
- **Second defect, even once wired:** the `audit("login"|"setup"|"refresh"|"forgot_password"|"reset_password")` entries can never fire. Those paths are public, so the request has no user and `AuditLog` skips it (internal/middleware/audit.go:32).
- **Verdict:** CONFIRMED.
- **Fix:** pass `WithAuditStore(store)` in main and add a wiring test. Record auth events inside the handlers, using the user the handler resolved.

**2. HIGH · authz · routes.go:277, 283, 357-359, 427, 442, 553, 575, 584-593, 690-692, 721-728, 770, 814**
- **Defect:** the viewer role is the default for new users (service/auth.go:70). Many mutating routes have no `RequireRole`, and no service checks a role anywhere.
- **Scenario:**
  - A viewer posts to `POST /conversations/{id}/messages` with `{"agentic":true,"mode":"coder"}`. The mode in the body bypasses the editor-only `/mode` route, and the agent edits files and runs bash in the workspace. Writing a file directly (`PUT /files/content`) needs editor, and stopping the run (`/stop`) needs editor too, so the viewer can start it but not stop it.
  - The same viewer can start an agent run through `/goals/ai-discover`.
  - A viewer can create or edit:
    - microagents and skills, which are injected into every user's runs (prompt injection into editors' agents);
    - memories and team shared-context items;
    - routing outcomes, which poison the tenant's model routing;
    - the tenant's VCS accounts (add and delete);
    - LSP servers (start), which is the KI-83 execution path;
    - retrieval scope membership;
    - runs (resume, fork, rewind);
    - other members' channel notify settings (`members/{uid}` is not compared with the caller).
- **Verdict:** CONFIRMED.
- **Fix:** require admin or editor for every non-GET route by default, with an explicit allowlist (`/me/*`, `/auth/*`, `/ws/ticket`, marking a channel read). Add a route-table test.

**4. MEDIUM · tenant isolation · routes.go:708-715, handlers_settings.go:37-95, service/tenant.go:36-71**

**5. MEDIUM · tenant isolation / cross-language · middleware/auth.go:158-166, workers/codeforge/agent_loop.py:1225-1250, consumer/_conversation_routing.py:92-110, service/routing.go:55-76**
- **Defect 1:** worker-to-Core HTTP calls use the internal key, which is a fixed default-tenant admin. Every tenant's routing outcomes are therefore stored in the default tenant, and the bandit's routing stats come from the default tenant for everyone. Default-tenant users see other tenants' run IDs, models and costs in `GET /routing/outcomes`.
- **Defect 2:** the `GetStats` cache key is `taskType:tier` with no tenant. Tenant A gets tenant B's cached stats for 5 minutes. A single global `cacheAt` also keeps old entries "fresh" whenever any key refills.
- **Verdict:** CONFIRMED.
- **Fix:** pass the tenant explicitly (or publish outcomes over NATS with `tenant_id`); key the cache by tenant, with a timestamp per entry.

**6. MEDIUM · correctness · main.go:1058, handlers_project.go:165/239/315, adapter/gitlocal/provider.go:72, handlers_a2a.go:212-216**
- **Defect:** `chimw.Timeout(30s)` cancels `r.Context()` for every API route, and long synchronous work runs on that context.
- **Scenario:**
  - Cloning, setting up or pulling a repo that takes more than 30 s kills git (`CommandContext`) and leaves a partial directory. The response is a 500 followed by a superfluous 504.
  - Retrying goes through the reclone path and is killed again, so large repos can never be cloned.
  - The `/a2a/tasks/{id}/subscribe` SSE stream ends after 30 s without a done event.
  - Synchronous LLM calls (decompose, plan-feature) fail with slow local models.
- **Verdict:** CONFIRMED for clone and SSE.
- **Fix:** exempt streaming routes; run clone and setup as background jobs with their own deadline.

**7. MEDIUM · unsafe default / DoS · docker-compose.prod.yml (core env), docker-compose.blue-green.yml, frontend/nginx.conf:33-37, middleware/ratelimit.go:162-171**
- **Defect:** both shipped topologies put nginx or Traefik in front of the Core, but `server.trusted_proxies` stays empty. Every unauthenticated client is therefore keyed by the proxy's IP. This is a follow-up to KI-11.
- **Scenario:**
  - All users share one auth limiter bucket (burst 5, 10 per minute). One client sending a bad login every 6 s keeps login, setup and password reset at 429 for everyone.
  - Webhooks and logins share a single 10 rps bucket.
  - Audit and consent records store the proxy's IP.
- **Verdict:** CONFIRMED (config).
- **Fix:** set `CODEFORGE_TRUSTED_PROXIES` in both compose files.

**10. MEDIUM · unsafe default · adapter/mcp/server.go:93-103, adapter/mcp/auth.go:13-31, config.go:625, loader.go:314-318**

**11. MEDIUM · correctness / security · middleware/idempotency.go:59-105**
- **Defect:**
  - No in-flight reservation: a retry with the same key during a slow `POST /runs` starts a second run.
  - Any status is cached for 24 h, so a transient 500 is replayed for a day.
  - The key is not bound to method, path or body.
  - Public routes use the raw header as the key, so a cached login response, including its `Set-Cookie` refresh token, is replayed to anyone who sends the same key.
  - Plaintext API keys from `POST /auth/api-keys` sit in NATS KV for 24 h.
- **Verdict:** CONFIRMED by reading. No first-party client sends the header, so this affects API clients only.
- **Fix:** reserve the key with `kv.Create`, cache 2xx/4xx only, bind the key to a hash of method, path and body, and skip auth routes and secret-bearing responses.

**12. MEDIUM when `lsp.enabled` · authz / tenant isolation · routes.go:721-728, handlers_agent_features.go:130-300, service/lsp.go:266**

### Checked and found OK
- **Auth path matching:** the public-path checks cannot be bypassed against chi routing. There is no path-cleaning middleware, and chi matches the raw path literally.
- **WebSocket ticket flow:** tickets are single-use, expire after 30 s and are bound to a tenant; a ticket is required before the upgrade; `DropUser` runs on token invalidation; Go's hijack clears the server deadlines.
- **Client IP:** forwarding headers are honoured only from trusted proxies.
- **A2A auth:** constant-time compare across all keys; the key's tenant overrides the header tenant; requests fail closed when no keys are configured.
- **Webhooks:** each webhook has its own secret, the tenant comes from the registration, `X-Tenant-ID` is never read, and bodies are capped at 10 MB.
- **CORS:** no origin reflection, and the wildcard is refused outside development.
- **Stores and handlers:** user update and delete, API keys, LLM keys and settings are scoped to the tenant.
- **Admin routes:** the platform-admin routes for KI-75 and KI-80, the admin-only knowledge-base routes (KI-105) and the setup token (KI-119) are in place.
- **Config:** `_FILE` secrets with conflict detection; JWT secret length, entropy and blocklist checks; bcrypt bounds; SIGHUP reload logs setting names only.
- **Shutdown:** the phase order is HTTP, then subscribers, then NATS drain, then DB close.
- **Frontend routes:** every frontend API client call hits a registered route (checked with a script, review-notes/R1/routes_cmp.py).
