## R4 review: Go services for context, knowledge, roadmap, benchmarks, prompts, A2A, LSP (snapshot 71bdf542)

I found 15 defects in my area. Five of them I reproduced with scratch tests, and the rest I traced through the code. The scratch tests are in `scratchpad/review-notes/R4/spec/` (a nested Go module that points at the snapshot). The temporary database I used for one check has been dropped.

### Findings, most severe first

**1. HIGH: every conversation turn tells the agent it is in PLAN mode, stuck, over budget and out of context (correctness, prompt assembly)**
- **Where:**
  - `internal/service/prompts/reminders/*.yaml`: none of the 7 reminders has `conditions`.
  - `internal/service/conversation_prompt.go:240-272`: `EvaluateReminders` renders every reminder unconditionally.
  - `internal/service/prompt_assembler.go:131-144`: on a template error, `renderEntry` silently returns the raw content.
- **Defect:** the reminders are meant to fire on runtime conditions. Instead, all 7 go into the assembled system prompt (category reminder matches every context), and all 7 go again into `reminders` on every dispatch, which the worker appends as `<system-reminder>` blocks.
- **Failure scenario:** the first turn of an agentic coder conversation contains "You are in PLAN mode … Do not execute changes", "No meaningful progress detected in 0 iterations … stuck in a loop", "You have used 0% of the cost budget ( / ). Wrap up", "approaching the context window limit" and "drifting from scope". Each appears twice. In the system-prompt copy the template is literally `{{.BudgetPercent}}`, because `conversationPromptData` (`conversation.go:28`) has no such field. This probably feeds KI-153 (model plans instead of coding) and KI-160 (9.2k-token prefix).
- **Evidence:** `TestReminders` gives 7 reminders on turn 1. `TestAssemble` shows lines like `WARNING: You have used {{.BudgetPercent}}% …` and `You are in PLAN mode…`.
- **Verdict:** CONFIRMED.
- **Fix:** give the reminders conditions (stall count ≥ N, budget ≥ 80 %, plan mode only, and so on), evaluate those in `EvaluateReminders`, and exclude `CategoryReminder` from `Assemble`. Log template errors instead of returning the raw text.

**2. HIGH: "Sync to file" destroys the spec file (data loss, roadmap sync)**
- **Where:**
  - `internal/service/roadmap_sync.go:128-149` and `155-225`
  - `internal/adapter/markdownspec/provider.go:91-122`
  - `internal/adapter/markdownspec/parser.go:58`
- **Defect:** the item-writer path is documented as "preserving the original file structure", but it re-renders the whole file:
  - `SpecItemDetail` has no Description, so `ParseItems` → `WriteItems` keeps only heading and list lines.
  - Paragraphs, tables, links, numbered lists, `####` headings, indentation and code fences are dropped.
  - `#` lines inside code blocks become H1 headings.
  - A line over 64 KiB stops the scanner silently (`scanner.Err` is unchecked), so everything after that line is dropped.
  - Without line `spec_ref`s, the fallback overwrites ROADMAP.md, TODO.md or docs/todo.md entirely with the rendered roadmap.
  - Any file named in a user-set `spec_ref` (for example `go.mod#L1`) is rewritten the same way.
- **Evidence:** `TestRoundTrip`. A TODO.md with an intro, a code block, a numbered list and a table comes out as 5 lines, and `- [x] Done item` becomes `- [ ]`.
- **Verdict:** CONFIRMED.
- **Fix:** patch only the status markers on the referenced lines, after checking that the line still has the same title. Never re-render the whole file, and refuse the full-render fallback when the file already exists.

**3. HIGH: spec import reverses done items and feeds every heading to the auto-agent (correctness, roadmap import)**
- **Where:**
  - `internal/service/roadmap_import.go:295-298` and `326-331`
  - `roadmap_sync.go:243-252`
  - automatic import at project setup: `project_workspace.go:511`
- **Defect:** `CreateFeatureRequest` has no status, so every imported item becomes `backlog`, including `[x]` items and every H1–H3 heading or plain list item. Re-import only updates titles, so status never flows from the file to the database.
- **Failure scenario:**
  - Sync-to-file maps backlog to `[ ]`, which unchecks every done item in the repository.
  - Auto-agent (`autoagent.go:404` takes backlog) re-implements done items and treats headings like "Known Issues" as features.
  - `spec_ref` is keyed by line number, so inserting one line duplicates every feature below it on re-import and points stale features at the wrong lines.
- **Verdict:** CONFIRMED by code trace (default `backlog` in the migration).
- **Fix:**
  - Import the item status and only checkbox items, or offer headings as milestones.
  - Match items by title or anchor rather than by line.
  - Detect conflicts before writing back.

**4. MEDIUM: the A2A client cache ignores the lookup failure, which allows cross-tenant use and a nil dereference that crashes the Core (tenant isolation, crash)**
- **Where:** `internal/service/a2a.go:523-529` and `177`
- **Defect:**
  - On a cache hit, the `GetRemoteAgent` error is discarded (`ra, _ :=`), so the cached client of any tenant, or of a deleted or disabled agent, is used.
  - `Enabled` is never checked.
  - If the send then fails, `ra.Name` dereferences nil.
- **Failure scenario:** a handoff to `a2a://<id>` runs in a NATS handler goroutine that has no `recover` (`internal/adapter/nats/nats.go:401`), so the panic kills the Go Core. Over HTTP it is a 500.
- **Evidence:** `TestNilRemoteAgent`: first call returns `connection refused`, second call panics with `invalid memory address or nil pointer dereference`.
- **Verdict:** CONFIRMED.
- **Fix:** always resolve the agent in the caller's tenant and fail on any error. Key the cache by tenant and ID, and reject disabled agents.

**5. MEDIUM: agent memories have a client-chosen tenant and no tenant filter on recall (tenant isolation)**
- **Where:** `internal/service/memory.go:38-54` and `58-99`
- **Defect:**
  - `Store` publishes the HTTP body's `tenant_id` unchanged (no `outgoingTenant`). The worker inserts `req.tenant_id`, defaulting to the zero UUID (`workers/codeforge/memory/models.py:59`).
  - Recall filters only `project_id = %s` (`_memory.py:151`).
  - The handlers check neither the project nor the role.
- **Failure scenario:** a viewer in tenant B can write memories into any tenant with `{"tenant_id": A}`, and can read A's memories via `/projects/<A-project>/memories/recall`. Memories that non-default tenants store through the API land in the default tenant and never show in their own list.
- **Verdict:** CONFIRMED by trace.
- **Fix:** set `TenantID` from the context in Go, verify the project, filter recall by tenant, and require editor for store.

**6. MEDIUM: A2A discovery and sending have no outbound policy (SSRF); KI-104's description is wrong**
- **Where:** `a2a.go:54`, `68-74`, `552`
- **Defect:**
  - `agentcard.DefaultResolver` and `a2aclient.NewFromCard` use plain `http.Client`s; only push webhooks use `SafeTransport`.
  - An editor's URL is fetched as-is.
  - The remote card's `url` (attacker-controlled) receives the JSON-RPC POSTs, so the Core can be made to POST to internal hosts.
  - The card body is read with an unbounded `io.ReadAll`.
- **Evidence:** `TestRegisterLoopback` registers a `127.0.0.1` agent successfully.
- **Verdict:** CONFIRMED.
- **Fix:** pass `agentcard.NewResolver` and the factory's transport options a client built on `netutil.OutboundPolicy` with a size cap. Correct KI-104, which says A2A uses `SafeTransport`.

**7. MEDIUM (when `lsp.enabled`): LSP start/stop race panics and orphans servers; LSP routes have no tenant check (correctness, isolation)**
- **Where:**
  - `internal/service/lsp.go:62-66`, `76-83`, `103-105`
  - routes in `internal/adapter/http/handlers_agent_features.go:129-280`
- **Defect:**
  - `StopServers` during `StartServers` makes `s.clients[projectID][lang] = client` write to a nil map, and the started server is never stopped.
  - Concurrent starts, or a non-ready client, replace the map entry without calling `Stop`, which leaks the process.
  - Every LSP route except start uses only the URL project ID, and the service is keyed by project ID only, so stop, status, diagnostics, hover and symbols work across tenants.
  - Start has no role check, so a viewer can start language servers (see KI-83).
- **Evidence:** `TestStopDuringStart` panics with `assignment to entry in nil map` and `stopped=0`.
- **Verdict:** CONFIRMED.
- **Fix:** re-check the map under the lock after `Start` and stop the client if the project was stopped. Stop replaced clients, check the project tenant on all routes, and require editor.

**8. MEDIUM: prompt evolution cannot store a second variant, and variants are never used (feature not wired)**
- **Where:**
  - `prompt_evolution.go:94-104`
  - `prompt_assembler.go:75`
  - `prompt_selector.go:50`
- **Defect:**
  - Variants are inserted into `prompt_sections` with an empty name and scope, which violates `UNIQUE (tenant_id, scope, name)` from the second variant of each tenant on. The result is a handler error, retries, and then the DLQ.
  - The selector runs only in `AssembleWithFingerprint`, which has no production caller (`conversation_prompt.go:184` uses `Assemble`).
  - If it were wired, `SelectVariant` would look up entry IDs (`mode.coder`) while variants are stored by mode ID (`coder`), and with `context.Background()` it would read the default tenant's variants for everyone.
- **Evidence:** in a private database, the second insert fails with `duplicate key … prompt_sections_tenant_id_scope_name_key`.
- **Verdict:** CONFIRMED.
- **Fix:** give each variant a unique name (for example `variant:<mode>:<family>:<version>`), wire the selector with the caller's context, and use mode IDs consistently.

**9. MEDIUM-LOW: A2A task state is not guarded and completions are dropped (correctness, NATS settle)**
- **Where:** `a2a.go:474-501` and `505-519`
- **Defect:**
  - `HandleTaskComplete` overwrites any state.
  - The worker ignores `a2a.task.cancel` (`_a2a.py:97-112`), so a cancelled task flips to `completed` or `failed` and push notifications fire.
  - Handlers run in parallel goroutines, so a late `working` message can land after a terminal state. Version conflicts and DB errors are logged and acked (`return nil`), which loses the completion.
- **Verdict:** CONFIRMED (overwrite and swallowed error); the ordering race is PLAUSIBLE.
- **Fix:** never leave a terminal state, and return errors so the message is retried or dead-lettered.

**10. LOW-MEDIUM: A2A push tokens are visible to any user; A2A mutations have no role check (secrets in API, authz)**
- **Where:**
  - `internal/port/database/types.go:23` (`json:"token"`)
  - `internal/adapter/http/routes.go:788-800`
- **Defect:**
  - `GET /a2a/tasks/{id}/push-config` returns each config's Bearer/HMAC token to viewers, who can then forge signed deliveries.
  - A viewer can create push configs, cancel tasks and trigger discovery.
- **Verdict:** CONFIRMED.
- **Fix:** redact the token, and require editor on these routes.

**11. LOW-MEDIUM: benchmark result handling is not idempotent; benchmark system jobs see only the default tenant**
- **Where:**
  - `benchmark.go:291` and `345`
  - `benchmark_watchdog.go:27`, started from `cmd/codeforge/main.go:898` with `context.Background()`
  - `benchmark_suite.go:33`
- **Defect:**
  - Results are inserted before `UpdateRun`, with no unique key. A transient error on `UpdateRun` leads to a retry and duplicate result rows, which doubles cost and leaderboard figures.
  - `CreateBenchmarkResult` errors are swallowed and the run is still marked completed.
  - The watchdog lists and updates only the zero-tenant runs, so other tenants' orphaned runs stay `running` forever (benchmark runs have no heartbeat).
  - Suites are seeded only for the default tenant.
- **Verdict:** CONFIRMED.
- **Fix:**
  - Add `UNIQUE(run_id, task_id, rollout_id)` with `ON CONFLICT DO NOTHING`.
  - Make the watchdog query intentionally cross-tenant and process each run in its own tenant context.

### Checked and found OK
- **Knowledge-base content (KI-105):** confinement to the tenant area via `workspacefs.OpenBelow` holds; the update path cannot change `content_path`; the fallback read is capped at 8 KiB.
- **Benchmark datasets (KI-107):** resolution goes through `operatorDir` and `os.Root`; listing does not follow symlinks.
- **Workspace scans:** context scoring and roadmap detection read through `workspacefs`; markdown spec reads and writes go through `os.Root` and cannot leave the workspace.
- **Templates:** only embedded YAML and `.tmpl` files are executed as templates; untrusted data is passed only as values (no template injection).
- **Tenant propagation:** retrieval, graph and repomap payloads carry the tenant (payload or the echoed header). Store queries for a2a, roadmap, knowledge bases, scopes, skills, microagents, benchmarks, repo maps and shared context all filter by tenant. The retrieval and search handlers verify the project.
- **A2A push delivery** uses `SafeTransport`, and A2A tasks, push configs and remote agents are tenant-scoped in the store.
- **Bounds:** microagent regex input is capped; context packing respects the token budget; adaptive, phase and complexity budget arithmetic is fine.
- Workers' memory and A2A consumers were read only as needed to trace Go findings; the text tool protocol was skipped as instructed.
