## Findings (most severe first)

**1. HIGH, authz: viewers can start agent runs.**
- **Where:** `internal/adapter/http/routes.go:277,283,814` (also `:789,794,796,801`).
- **Defect:** `POST /projects/{id}/conversations`, `POST /conversations/{id}/messages` and `POST /projects/{id}/goals/ai-discover` have no `RequireRole`. Stopping, clearing, mode, model, fork and rewind all require editor. No global viewer guard exists (`rbac.go`, `main.go:1037`). The chat UI shows the input to every role.
- **Scenario:** a viewer (the docs call it "read-only") sends a message in a project with a workspace. An agentic run starts, spends budget, and under an autonomous profile writes files and runs bash. The viewer cannot even stop it, because `/stop` needs editor.
- **Also open to viewers:** cancelling A2A tasks, creating and deleting push configs, and remote-agent discovery.
- **Verdict:** CONFIRMED by route trace; the handler has no role check.
- **Fix:** `RequireRole(admin, editor)` on these routes, and hide the chat input for viewers.

**2. MEDIUM, authz: editors can delete projects through the batch endpoint.**
- **Where:** `routes.go:174` vs `:183`; `handlers_batch.go:32-46`.
- **Defect:** the single `DELETE /projects/{id}` is admin-only and audited. `POST /projects/batch/delete` allows editors, writes no audit entry, and calls the same `Projects.Delete`.
- **Scenario:** an editor uses Dashboard > Select > Delete and removes any project in the tenant, with no audit trail.
- **Verdict:** CONFIRMED.
- **Fix:** admin-only plus `audit("delete","project")` per ID.

**3. MEDIUM, auth: logout fails open.**
- **Where:** `frontend/src/components/AuthProvider.tsx:108-118`; `handlers_auth.go:106-110`; `internal/middleware/auth.go:26-48` (`/auth/logout` is not public).
- **Defect:** logout needs a valid bearer token. On a 401 the frontend still clears its local state, but the server's refresh tokens and the httpOnly cookie stay valid.
- **Scenario:** the access token has expired or been invalidated (KI-143 epoch bump, or the refresh retry path after a network error). The user clicks Logout, gets 401, and lands on /login. The next page load restores the session from the cookie, which matters on a shared machine.
- **Verdict:** CONFIRMED (mechanism).
- **Fix:** let logout work with the refresh cookie alone (revoke that token and clear the cookie). Alternatively the frontend refreshes and retries on 401.

**4. MEDIUM, auth: concurrent refresh across tabs logs users out.**
- **Where:** `AuthProvider.tsx:67-85,131-146`; `service/auth_token.go:44-94`; `store_refresh_token.go:73-103`; `handlers_auth.go:76-89`.
- **Defect:** every page load POSTs `/auth/refresh` with the shared cookie. Rotation deletes the old token row, so the second concurrent request fails and its response clears the cookie (MaxAge -1).
- **Scenario:** the user middle-clicks several project links, or the browser restores several tabs. The losing tabs land on /login. If the failing response's Set-Cookie arrives last, the winner's new cookie is deleted too, and every tab is logged out at its next refresh.
- **Verdict:** CONFIRMED on the server side; the browser cookie ordering is PLAUSIBLE.
- **Fix:** serialize refreshes with `navigator.locks` or a BroadcastChannel, and add a short server grace window for a just-rotated token (do not clear the cookie on a rotation conflict).

**5. MEDIUM, resilience: one failed GET replaces the whole app with the error screen.**
- **Where:** `App.tsx:455` holds the only boundary.
- **Defect:** Solid throws when an errored resource is read, and nothing catches it below the app root. Unguarded reads:
  - `features/channels/ChannelList.tsx:16,24,57` (mounted on every page)
  - `features/dashboard/DashboardPage.tsx:35-36` (the `healthMap` source reads `projects()` and bypasses the inline `projects.error` alert) and `:173`
  - `ChartsPanel.tsx:73-97`
  - `costs/CostDashboardPage.tsx:26-27`
  - `channels/ChannelView.tsx:225,339` (a deleted channel returns 404)
  - `ui/composites/ModelCombobox.tsx:80-83`
- **Scenario:** the Core restarts or nginx returns 502 for longer than the 7 s of retries. GET /channels fails and every page shows "Something went wrong".
- **Evidence:** `review-notes/R10a/resource_error.cjs` and `resource_source_error.cjs` (Solid 1.9.11) both print "caught by App ErrorBoundary".
- **Verdict:** CONFIRMED.
- **Fix:** guard reads with `res.error` / `res.state === "ready"`, or add per-section ErrorBoundaries.

**6. MEDIUM, error hiding and rule violation: chat slash commands ignore HTTP status.**
- **Where:** `features/chat/commandExecutor.ts:37-119`; `features/project/ChatPanel.tsx:254-263`.
- **Defect:** `/clear`, `/compact`, `/mode` and `/model` use raw `fetch()` (AGENTS.md requires the API client) and never check `res.ok`.
- **Scenario:** a viewer types `/clear` and gets 403, but the toast says "Conversation cleared.". `/mode foo` returns 500 (unknown mode), but the toast says "Mode switched to foo". `/model` refused with a 409 shows success too.
- **Verdict:** CONFIRMED.
- **Fix:** use `api.conversations.*` through the core client and surface errors.

**7. MEDIUM, audit correctness: "Load more" returns random entries.**
- **Where:** `internal/adapter/postgres/eventstore.go:385-387,424-427`; `features/audit/AuditTable.tsx:36,200`; `migrations/021_create_sessions.sql:29`.
- **Defect:** the cursor is the last entry's random UUID and the next page filters `id > cursor` while ordering by `created_at DESC`.
- **Scenario:** in Activity > Audit, a second page repeats some entries and silently omits others.
- **Verdict:** CONFIRMED.
- **Fix:** keyset cursor `(created_at, id) < ($ts, $id)`.

**8. LOW-MEDIUM, contract: the Activity page misreads WS payloads.**
- **Where:** `features/activity/ActivityPage.tsx:89-99,110-145`; `domain/event/broadcast_payloads.go:11-16,34-38,71-79,96-100`.
- **Defect:** the page reads `p.passed`, but the Go `QualityGateEvent` sends `status`. It reads `name`/`title`, but the agent, task and plan events carry neither.
- **Scenario:** every gate event, including "started" and "passed", shows as "Quality gate failed" in red, and agents, tasks and plans show with blank names.
- **Verdict:** CONFIRMED.
- **Fix:** map `status`, and use IDs or add the fields.

**9. LOW, dead feature: the dashboard Activity timeline listens for event types never broadcast.**
- **Where:** `features/dashboard/ActivityTimeline.tsx:18-32`.
- **Defect:** `run.failed`, `run.completed`, `agent.error` and `plan.completed` are trajectory types that arrive inside `trajectory.event`. Only `task.status` and `run.budget_alert` are real WS types.
- **Scenario:** failures and completions never appear in the timeline.
- **Verdict:** CONFIRMED (grep of every `BroadcastEvent` type).
- **Fix:** subscribe to `trajectory.event` and key on `event_type`, or use `run.status`.

**10. LOW, UI correctness: KPI shows "$NaN".**
- **Where:** `features/dashboard/KpiStrip.tsx:5-35`.
- **Defect:** for 0 < value < 0.5, `Math.round(num)` is 0, so the ratio is 0/0.
- **Scenario:** Cost Today $0.42 renders as "$NaN"; error rate 0.3% renders as "NaN%".
- **Evidence:** `review-notes/R10a/kpi.cjs` prints `$0.42 -> $NaN`.
- **Verdict:** CONFIRMED.
- **Fix:** animate the float, or return the original string when the rounded value is 0.

**11. LOW, broken downloads: benchmark export links send no credentials.**
- **Where:** `features/benchmarks/BenchmarkPage.tsx:272`; `CostAnalysisView.tsx:127-140`; `api/resources/benchmarks.ts:52,66`.
- **Defect:** plain `<a href="/api/v1/...">` links carry no Authorization header, and the auth middleware is bearer-only.
- **Scenario:** the CSV export opens `{"error":"authorization required"}` instead of a file. `TrajectoryPanel.tsx:291` (outside this area) has the same issue.
- **Verdict:** CONFIRMED.
- **Fix:** fetch through the client and save the Blob.

**12. LOW, stale state when switching channels.**
- **Where:** `features/channels/ChannelView.tsx:59-60,250-268,343-351`.
- **Defect:** the route component is reused, but `webhookKey` and `threadParent` are never reset when `params.id` changes.
- **Scenario:** channel A's freshly generated key is shown next to `/api/v1/webhooks/channels/<B>`. A's open thread stays open, and a reply posts to B with A's parent and fails with 404.
- **Verdict:** CONFIRMED.
- **Fix:** reset both in an effect on `params.id`.

**13. LOW, missing pagination: channels and threads see only the newest 50 messages.**
- **Where:** `ThreadPanel.tsx:74-80`; `ChannelView.tsx:81`; `service/channel.go:92-100`.
- **Defect:** the cursor is never used.
- **Scenario:** in a busy channel, older top-level messages are unreachable, threads of older parents show empty, and reply counts drop.
- **Verdict:** CONFIRMED.
- **Fix:** cursor paging, plus a parent filter for threads.

**14. LOW, stale after reconnect: a concrete path for KI-159.**
- **Where:** `components/ConversationRunProvider.tsx:20-36`; `features/project/ChatPanel.tsx:199-204`; `useChatAGUI.ts:333-341`.
- **Defect:** nothing resyncs after a WS reconnect. A missed `agui.run_finished` (reconnect gap, or another replica per KI-139) leaves the run in `activeRuns` forever. ChatPanel then forces `setAgentRunning(true)`, and `restoreRun` returns on `!state.active` without clearing it.
- **Scenario:** the chat shows "running" indefinitely and the sidebar shows "1 run active".
- **Verdict:** PLAUSIBLE.
- **Fix:** clear `activeRuns` from `runState` and on reconnect, and set `agentRunning(false)` when the run is inactive.

**15. LOW, auth leftovers: logout, user change and session expiry leave earlier state behind.**
- **Where:** `features/notifications/notificationStore.ts:40`; `ConversationRunProvider`; `api/cache.ts:56`; `AuthProvider.tsx:74-80`.
- **Defect:** notifications, `activeRuns` and the offline action queue are never cleared on logout or user change. The GET cache is cleared on logout but not when the session expires.
- **Scenario:** the next user in the same tab sees the previous user's run errors and IDs.
- **Verdict:** CONFIRMED.
- **Fix:** clear all of these when the session user changes.

**16. LOW, duplicate side effects.**
- **Where:** `api/core.ts:110-124,137-141`; `api/cache.ts:56-93`.
- **Defect:** a network `TypeError` retries POSTs up to 3 times. When offline, mutations are parked in a pending promise and replayed later with whatever token is current.
- **Scenario:** a connection reset after the server accepted the request re-sends `POST /runs` or a message, or re-uses a rotated refresh token. Logout while offline never resolves.
- **Verdict:** PLAUSIBLE.
- **Fix:** do not retry non-idempotent methods, and drop the queue on logout.

**17. LOW, error hiding: batch results are discarded.**

- **Scenario:** delete and pull toast success even when every item failed, and "Status" discards the git status it fetched.

**18. LOW, error hiding: the WS banner and API dot misreport.**
- **Where:** `components/OfflineBanner.tsx:33-42`; `App.tsx:333-339,360-368`.
- **Defect:** the banner effect returns early during the first 3 s, and `connected()` never changes if the WS never connects, so the banner never shows. The API status dot is always green.
- **Scenario:** a deployment whose `/ws` is not proxied shows no banner, and the dot stays green next to "API: unavailable".
- **Verdict:** CONFIRMED.

**19. LOW, contract: the benchmark RoutingReport never appears, and Cancel doesn't stop the worker.**
- **Where:** `port/messagequeue/schemas_benchmark.go:53-60`; `service/benchmark.go:339-342`; `handlers_benchmark.go:101-122`.
- **Defect:** the worker adds `summary["routing_report"]`, but Go's `BenchmarkSummary` struct drops it, so `BenchmarkPage.tsx:348` never finds it (the feature is claimed in `docs/project-status.md:197`). Benchmark "Cancel" only flips the DB status; there is no cancel subject.
- **Scenario:** auto-routed runs show no report, and a "cancelled" benchmark keeps running and spending.
- **Verdict:** CONFIRMED. Dev mode only.

**20. LOW, UX: approval links and the approval page.**
- **Where:** `App.tsx:174-183`; `features/approvals/ApprovalPage.tsx:44-47`.
- **Defect:** permission notifications link to the currently viewed project, not the run's project, even though `/approvals/:runId/:callId` exists. The approval page shows "not pending" for 403, 500 and network errors.
- **Scenario:** a viewer opening an email link is told the approval is not pending.
- **Verdict:** CONFIRMED.

**21. LOW, data loss: chat text starting with "/" is swallowed.**
- **Where:** `features/project/ChatPanel.tsx:233-252`; `commandExecutor.ts:147`.
- **Defect:** any text starting with "/" is treated as a command, and the input is cleared before dispatch.
- **Scenario:** pasting "/home/user/app.py fails…" shows "Unknown command" and the text is lost.
- **Verdict:** CONFIRMED.
- **Fix:** intercept only known command IDs, and keep the input on unknown ones.

**22. LOW, secret in an API response: A2A push-config bearer tokens.**
- **Where:** `handlers_a2a.go:153-161`; `port/database/types.go:23`.
- **Defect:** `GET /a2a/tasks/{id}/push-config` returns the raw token to any role. The UI masks it, but the API does not.
- **Verdict:** CONFIRMED.
- **Fix:** redact (`has_token`) and gate the route by role.

**23. LOW, memory: the GET response cache is unbounded.**
- **Where:** `api/cache.ts:24-38`.
- **Defect:** every GET (file contents, the 10k-entry file tree, trajectories) is kept for the life of the tab and evicted only when re-read after 5 min.
- **Scenario:** a long session grows memory, and the offline fallback serves stale file content after a write.
- **Verdict:** PLAUSIBLE.
- **Fix:** an LRU or size cap, and invalidate on write.

## Checked and OK
- **Markdown renderer:** escapes before inline markup, uses an http(s)/mailto allowlist and quote-escaped hrefs. No `innerHTML` elsewhere in this area, and no `javascript:` link sinks.
- **Canvas:** SVG `<image>` from a data URL; no script path.
- **Token storage:** access token only in memory; refresh cookie httpOnly, `Path=/api/v1/auth`, SameSite=Lax.
- **`safeNextPath`:** blocks `//`, `/\` and control characters.
- **Route guard:** fails closed, compares paths lowercased.
- **WS ticket flow:** a ticket per attempt, stale tickets discarded, closed on logout and while the password must be changed, no JWT in the URL.
- **Listener and interval cleanup:** done in all components reviewed (WS subscriptions, keydown handlers, Tooltip, SetupPage interval apart from a tiny unmount race).
- **i18n:** en and de have identical key sets (1795, no duplicates), the `{{placeholders}}` match, and every `tp()` key has `_one` and `_other`.
- **Types vs Go JSON:** costs, dashboard stats and charts, project health, A2A, channels (`parent_id` omitempty handled), audit page, benchmark run, suite, leaderboard and cost analysis, User (`is_platform_admin` comes from MarshalJSON), CommandInfo and AG-UI events all match.
- **Route coverage:** every path in `api/resources/*.ts` has a Go route.
- **Channel posts and thread replies:** the server attributes them to the caller and checks that the parent belongs to the same channel.
- **Known issues:** KI-162, KI-146, KI-120 and KI-139 were not re-reported (#14 is a new path for KI-159).
