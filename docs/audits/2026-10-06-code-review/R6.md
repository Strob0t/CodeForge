## R6 review: Go adapters (except http and postgres), internal/git, internal/workspacefs, internal/netutil. Snapshot 71bdf542

I found 16 issues. The most serious is a high-severity denial of service that any agent can trigger with one `mkfifo` (finding 1, reproduced). Scratch reproductions are in `scratchpad/review-notes/R6/` (`gitfifo/`, `pushcfg/`, `workers/`, `cred/`). All paths below are relative to the snapshot.

### 1. HIGH (security/DoS): a FIFO in the workspace hangs every Go Core git call and uses up the shared git pool
- **Where:** `internal/git/nested.go:113-114` (`ignoredDirs` runs `ls-files --exclude-standard`), `internal/git/workspace.go:394-402` (`runGit` has no deadline), `internal/service/checkpoint.go:119-124` (holds `lockRun` and a pool slot), `internal/service/runtime_execution.go:188` (the NATS tool-call handler's ctx has no deadline).
- **Defect:** git opens `.gitignore`, `.git/info/exclude`, `.gitattributes` and any `core.excludesFile` (an allowed key) with a blocking `open()`. `OpenRepo` runs such a command, and the workspace checks never refuse a FIFO in these places.
- **Scenario:**
  - The agent runs `mkfifo .gitignore`.
  - The next file-changing tool call checkpoints, and `OpenRepo` blocks forever while holding one of the 5 `git.Pool` slots (`config.go:696`).
  - Five such runs block every tenant's checkpoints, deliveries, review pipelines and rewinds.
  - Every file-changing tool call is then denied once the approval timeout expires, and goroutines leak through NATS redeliveries.
- **Evidence:** `git status`, `git add -A` and `ls-files --exclude-standard` all hang (git 2.43, `timeout` exit 124). A copy of `internal/git` called with a 3 s context: `OpenRepo returned after 3.003s: list ignored directories: git ls-files: : signal: killed`.
- **Verdict:** CONFIRMED.
- **Fix:** give every workspace git command a deadline (`context.WithTimeout` in `runGit`/`Repo.Run`). Refuse non-regular `.gitignore`/`.gitattributes`/`info/*` files and FIFOs/sockets in the nested walk. Refuse `core.excludesFile` pointing at anything but a regular file.

### 2. MEDIUM (security): delivery push goes wherever the agent's config says, with the Go Core's credentials
- **Where:** `internal/service/deliver.go:269`; `internal/git/config_keys.go:115` (`remote.url`, `remote.pushurl` and `remote.push` are allowed).
- **Defect:** `Push(..., "-u", "origin", branch)` follows `remote.origin.pushurl` and `remote.origin.push`. `RequireNetworkSafe` refuses neither.
- **Scenario:** the agent sets `remote.origin.push=+refs/heads/codeforge/<id>:refs/heads/main`, so delivery force-overwrites the remote `main`. With `pushurl`, the push goes to any repository the operator's SSH key can write, including other tenants' repositories.
- **Evidence:** reproduced: `+ a2c58c9...9e2ec95 codeforge/abc -> main (forced update)`. A push with a `pushurl` landed in a different bare repository.
- **Verdict:** CONFIRMED (git semantics plus allowlist).
- **Fix:** push to the project's stored URL with a full refspec, like `FetchFrom` does (`push -- <proj.RepoURL> refs/heads/X:refs/heads/X`). Or classify `remote.*.push`, `remote.*.pushurl` and a mismatching `remote.*.url` as refused for network operations.

### 3. MEDIUM (secrets in API responses): project credentials go to every tenant user
- **Where:** `internal/adapter/svn/register.go:10-15` (`cfg["password"]`), `internal/adapter/github/register.go:7` and `deliver.go:333` (`Config["token"]`), `internal/adapter/http/handlers_project.go:28-51`, `routes.go:158,178` (no role check), `internal/adapter/mcp/tools.go:75-104`.
- **Defect:** `project.Config` is returned verbatim by `GET /projects` and `GET /projects/{id}` (viewers included) and by the MCP server. Nothing redacts it.
- **Scenario:** a viewer reads the SVN password or the github-api PR token of any project in the tenant. The KI-87 argv fix is moot.
- **Verdict:** CONFIRMED (code read). This crosses into the HTTP review area.
- **Fix:** redact credential keys (`secrets.IsCredentialName`) on read, and keep the stored value when `***` is sent back (as MCP does).

### 4. MEDIUM (security): the built-in MCP server is unauthenticated by default on all interfaces
- **Where:** `internal/adapter/mcp/auth.go:15-20`, `server.go:103`, `cmd/codeforge/main.go:1134` (`":%d"`), `internal/config/loader.go:314-318` (there is no `CODEFORGE_MCP_API_KEY`).
- **Defect:** `mcp.enabled` with an empty `api_key` serves the default tenant's projects (including config secrets), runs and costs with no auth on `:3001`. Env-only deployments cannot set a key.
- **Scenario:** an agent tool process of any tenant (it can reach `core:*`, KI-110) calls `list_projects`/`get_run_status` on `core:3001`. The docs claim "Bearer token / API key middleware".
- **Also:** `resources.go:149-155`, the `codeforge://projects/{id}/costs` resource, returns the global cost summary, not the project's.
- **Verdict:** CONFIRMED.
- **Fix:** refuse to start without a key (or bind to loopback), add an env var, compare in constant time, and use the per-project cost reader.

### 5. MEDIUM (SSRF): `GET /projects/remote-branches` runs `git ls-remote` against any host for any user
- **Where:** `internal/service/project_git.go:311-330`, `routes.go:160` (no role check).
- **Defect:** only the scheme is checked (https/http/git/ssh). The git process bypasses `SafeTransport` and `OutboundPolicy`; KI-104 assumes project-git is covered.
- **Scenario:** a viewer sends `?url=git://postgres:5432/x` or `http://litellm:4000/...`. This gives raw TCP or HTTP GET from the Go Core to internal hosts, with a 502-versus-timeout port-scan oracle. Redirects are followed.
- **Verdict:** CONFIRMED (code read).
- **Fix:** resolve and check the host with `OutboundPolicy` first, pin it with `http.curloptResolve`/`url.<pinned>.insteadOf`, drop `git://`, and require editor.

### 6. MEDIUM (DoS): resource-control config keys are allowed, letting the agent fork-bomb the Go Core
- **Where:** `internal/git/config_keys.go:108` (`checkout.workers`, `checkout.thresholdForParallelism`), plus the `pack.*` and `index` sections and the `core.*` cache and limit keys.
- **Defect:** these keys are agent-writable data that sizes Go Core processes.
- **Scenario:** `checkout.workers=N` plus N files makes a rewind (`read-tree -u --reset`, `checkpoint_chain.go:356`) spawn N `checkout--worker` processes inside the 1 GiB core container. That means an OOM or PID exhaustion that kills the Go Core for all tenants.
- **Evidence:** repo config with 300 files: `GIT_TRACE` shows 300 worker spawns from one `read-tree -u`.
- **Verdict:** CONFIRMED.
- **Fix:** override `checkout.workers=1`, `index.threads=1`, `pack.threads=1` and sane `pack.windowMemory`/`core.packedGitLimit` values on the command line, or refuse these keys.

### 7. MEDIUM (correctness): the LiteLLM client uses a 10 s timeout for chat completions
- **Where:** `internal/adapter/litellm/client.go:64`, with completions sent through `doRequest` at lines 463 and 688.
- **Defect:** `ChatCompletion` shares the admin client's `Timeout: 10s`.
- **Scenario:** feature decomposition (`meta_agent.go:113`, 4096 max tokens) and the review router fail with `Client.Timeout exceeded` on almost any real model, especially local ones (KI-160). Each timeout also counts toward the LLM breaker.
- **Verdict:** CONFIRMED (code read).
- **Fix:** use a separate client or a per-call timeout for completions (minutes, bounded by ctx).

### 8. MEDIUM (resilience): the Go Core loses NATS for good after about 2 minutes of outage
- **Where:** `internal/adapter/nats/nats.go:82` (`MaxReconnects(60)`, 2 s wait), no `ClosedHandler`.
- **Scenario:** NATS is down for more than ~2 minutes, for example during an upgrade. The connection closes for good, runs never start again, and `/health/ready` stays 503. Compose `restart: unless-stopped` does not restart unhealthy containers.
- **Verdict:** CONFIRMED (nats.go semantics).
- **Fix:** use `MaxReconnects(-1)`, or a `ClosedHandler` that exits the process. The worker uses the same nats-py default of 60.

### 9. MEDIUM-LOW (resilience): the shared circuit breakers count per-request errors as outages
- **Where:** `internal/adapter/litellm/client.go:699-701` and `internal/resilience/breaker.go:57-58`; `nats.go:261-262`.
- **Defect:** any 4xx (an invalid model name in a decompose request, a bad `/model/new` body) and NATS `ErrMaxPayload` count as failures. Five failures open the breaker for 30 s, and one failure in half-open reopens it.
- **Scenario:** one editor's bad requests block model discovery and decompositions for everyone. With NATS, oversized publishes (PLAUSIBLE: long conversation starts) block every tenant's tool-call decisions, which then go to the DLQ.
- **Verdict:** CONFIRMED (LiteLLM path), PLAUSIBLE (NATS path).
- **Fix:** trip only on transport errors, 5xx and timeouts; never on 4xx, `ErrMaxPayload` or ctx cancellation.

### 10. LOW-MEDIUM (lost work): inbound A2A tasks stay "working" forever
- **Where:** `internal/adapter/a2a/executor.go:148-150`. There is no Go subscriber on `a2a.task.created.dlq`.
- **Defect:** a publish failure is only logged, but the task is already stored and reported as `working`. A dead-lettered `a2a.task.created` is never failed. This breaks the AGENTS.md rule that every work-carrying subject has a `.dlq` subscriber.
- **Verdict:** CONFIRMED.
- **Fix:** mark the task failed on publish error and add a DLQ subscriber that fails the task.

### 11. LOW (feature claimed, not wired): github-api "token-auth clone URLs"
- **Where:** `internal/adapter/github/provider.go:80` (`CloneURL` has no callers), `Clone` at line 177 uses `p.RepoURL`.
- **Scenario:** private repositories cannot be cloned or pulled with the project token (no helper, no prompt). PR delivery's https push fails, so the PR is skipped. The docs (`01-project-dashboard.md:97`) claim it works.
- **Verdict:** CONFIRMED.
- **Fix:** pass the token as `http.extraHeader` through `GIT_CONFIG_*` for that host only. Never embed it in `.git/config`.

### 12. LOW (functional): the SVN provider cannot be given svn://, svn+ssh:// or http:// repositories
- **Where:** `internal/domain/project/validation.go:113-118`, `project_workspace.go:248`.
- **Defect:** `IsValidRepoURL` allows only `https://` and `git@`, but the SVN adapter's `allowedSchemes` advertise http, svn and svn+ssh.
- **Verdict:** CONFIRMED.
- **Fix:** validate per provider.

### 13. LOW (argument injection): the checkout branch reaches git unchecked
- **Where:** `internal/adapter/gitlocal/provider.go:257`, `internal/adapter/github/provider.go:280`.
- **Defect:** `git checkout <branch>` has no `--end-of-options` or ref validation.
- **Scenario:** an editor sends `branch="-f"` or `"."`, which silently discards all uncommitted agent and user work in the workspace.
- **Verdict:** CONFIRMED (git semantics).
- **Fix:** run `check-ref-format --branch` and use `--end-of-options`/`switch`.

### 14. LOW (async/goroutine leak): SMTP approval mails have no timeout
- **Where:** `internal/adapter/email/notifier.go:46`.
- **Defect:** `smtp.SendMail` ignores ctx, so a stalled SMTP server leaks one goroutine per approval request.
- **Verdict:** PLAUSIBLE.
- **Fix:** dial with a deadline (`net.Dialer` plus `smtp.NewClient`).

### 15. LOW (rule violation): the re-clone path deletes the workspace in the Go Core
- **Where:** `internal/adapter/gitlocal/provider.go:129`, `internal/adapter/svn/provider.go:155`.
- **Defect:** both call `os.RemoveAll(workspace)` in the Go Core. With `tool_acls: required`, AGENTS.md says the worker deletes workspaces. Tool-UID files whose ACL mask was narrowed by chmod leave a half-deleted workspace.
- **Verdict:** PLAUSIBLE.
- **Fix:** delete through `workspace.delete.request`.

### Checked and OK
- **NATS:** messages are settled exactly once (ack, nak, Term plus DLQ copy, nak when the DLQ copy fails); `MaxDeliver` is 4; in-progress heartbeats stop at the limit; DLQ copies drop `Nats-*` headers.
- **NATS tenant and relay:** the `X-Tenant-ID` header loses to an explicit tenant (`Lookup`/`Explicit`), and publishes stamp `Lookup`. The relay acts only on `_INBOX_core.` replies.
- **WebSocket hub:** tenant-only fan-out, fail-closed without a tenant, bounded per-client queue with drop, write timeout, single-use tickets bound to a tenant, `DropUser`.
- **internal/git hardening:** credential helpers are reset even per URL (tested). Filters, hooks, fsmonitor, textconv, ext-diff and merge drivers are neutralised or refused, and only builtin subcommands run, so aliases cannot fire. Includes are not followed; gitlinks and nested repositories are refused.
- **Outbound HTTP:** `OutboundPolicy` (dial-time pinning, IPv4-in-IPv6, metadata), `SameOriginRedirect`, the githubapi, GitLab and githubpm clients (size caps, no token in errors, numeric issue IDs, operator token only for the default tenant).
- **Other adapters:**
  - **SVN:** URL scoping, password on stdin.
  - **workspacefs:** os.Root, O_NONBLOCK, regular-file checks.
  - **Spec providers:** use workspacefs.
  - **Slack and email:** escaping and the tenant filter.
  - **LiteLLM:** `/health` skips disabled-health routes.
  - **Backend adapters:** publish-only.
  - **execshell:** dead code.
