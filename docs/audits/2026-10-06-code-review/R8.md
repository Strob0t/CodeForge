## R8 review: Python worker core (snapshot 71bdf542)

I found 19 issues: 1 high, 11 medium, 7 low. I reproduced the defects marked "repro" with scratch scripts in `scratchpad/review-notes/R8/`; the others I traced through the code. None of them is an existing KI. Paths are relative to `workers/codeforge/` unless they start with `internal/`.

### 1. HIGH: the stall detector aborts normal edit/test loops
- **Where:** `stall_detection.py:54-77`, `agent_loop.py:521,545`.
- **Defect:** a "stall" means any identical (tool, args) entry 3 times among the last 5 calls, counted anywhere in the window. The escape prompt never clears the window, so once stalled the run always aborts 2 iterations later.
- **Scenario:** edit (different args each time) → `bash python -m pytest -q` → edit → pytest. Repro: stalled at iteration 6, again at 8, **abort at 9** with the error `stall detected: repeated None after 2 escape attempts`. The loop's own "verify after every write" nudge (`agent_loop.py:508`) provokes exactly this pattern. Go then re-plans plan steps or fails the turn.
- **Verdict:** CONFIRMED (repro).
- **Fix:** count consecutive repeats with no other call in between; clear the window after an escape.

### 2. MEDIUM: the tool router never offers MCP, skill or conversation-search tools
- **Where:** `tools/tool_router.py:97-123`, `loop_config.py:93`, `agent_loop.py:323-340`.
- **Defect:** any run with a user prompt gets `selected_tools` = BASE_TOOLS plus keyword hits. The filter then drops everything else.
- **Effect:** `mcp__*` tools (read-only ones are added only when the prompt has a docs keyword), `create_skill`, `search_skills` and `search_conversations` are never offered. No mode lists them. Project MCP servers are effectively unusable in runs and chats.
- **Verdict:** CONFIRMED (repro: "Please create a GitHub issue…" → `mcp__gh__create_issue` and `mcp__gh__search_issues` not offered).
- **Fix:** treat the router as a ranking, or always include MCP and wired tools.

### 3. MEDIUM: a conversation with an empty workspace makes the file tools work in the worker's own directory
- **Where:** `consumer/_conversation.py:676-681`, `tools/_base.py:67`, `workspace_fs.py:169`.
- **Defect:** `WorkspaceRoot("")` normalises to ".", i.e. the worker's CWD (`/app`, or the repository root in dev). The file tools run in the worker process, so neither the tool UID nor Landlock applies.
- **How it is reached:** `runs.start` refuses this (`executor.py:151`), but the conversation path does not. Go's `IsAgentic` returns `req.Agentic` before its workspace check (`internal/service/conversation_agent.go:58-60`), so `{"agentic": true}` on a project with no workspace starts such a run.
- **Repro:** `read_file` and `list_directory` with workspace "" read and list the CWD (`.env` content returned).
- **Fix:** fail the conversation run when `workspace_path` is empty or not a directory; fix `IsAgentic` in Go.

### 4. MEDIUM (tenant isolation): memory store and recall
- **Where:** `consumer/_memory.py:57-77,149-156`, `memory/models.py:59,73`.
- **Defects:**
  - Recall queries `WHERE project_id = %s` with no tenant filter.
  - Store inserts the payload's `tenant_id`. Go copies it straight from the HTTP body (`handlers_agent_features.go:294/309`); when it is absent the worker defaults to DEFAULT_TENANT_ID.
- **Scenario:** a tenant-B user posts to `/projects/<A-project>/memories/recall` and gets tenant A's memories. Normal stores of non-default tenants land in the default tenant, so the tenant-scoped `ListMemories` never shows them.
- **Verdict:** CONFIRMED (trace).
- **Fix:** take the tenant from the message header (`current_tenant()`), add `AND tenant_id = %s`, and overwrite TenantID in Go.

### 5. MEDIUM (data loss): multi-rollout conversations
- **Where:** `agent_loop.py:1092-1180`.
- **Defect:** rollout 0 runs `git stash push --include-untracked` and the stash is never popped. Later rollouts run `checkout .` and `clean -fd`. The workspace ends with the **last** rollout's changes while the result reports the "best" one.
- **Repro:** the user's uncommitted edit and untracked file vanish into `stash@{0}`; the workspace holds rollout 2 while rollout 1 is reported (`selected_index` 0).
- **Reach:** opt-in, `CODEFORGE_AGENT_CONVERSATION_ROLLOUT_COUNT>1` with autonomy ≥4.
- **Fix:** snapshot without touching user state (a worktree or commit), restore the best rollout, pop the stash.

### 6. MEDIUM: Stop, wall-clock timeout and worker abort leave tool processes running
- **Where:** `tools/bash.py:133-151`, `runtime.py:270-307`, `agent_loop.py:500,1006`.
- **Defect:** a cancel only sets a flag that is checked between calls. The bash tool is not started in its own session and is killed only on `TimeoutError`. A `CancelledError` (the 3600 s `wait_for`, or abort) leaves the process running. Heartbeats stop at cancel, so a stopped command keeps changing the workspace while the next turn may already run elsewhere.
- **Verdict:** CONFIRMED (repro: process alive after the task was cancelled).
- **Fix:** `start_new_session=True`, kill the group in `finally`, and have the runtime cancel interrupt the running tool.

### 7. MEDIUM: the bash `timeout` argument is not validated
- **Where:** `tools/bash.py:127,147`.
- **Defect:** `"timeout": "60"` (common with weak local models) raises TypeError inside `wait_for` after the process started. The process is never awaited or killed and its pipes stay unread. `null` means no timeout at all.
- **Verdict:** CONFIRMED (repro: `sleep 30` still running after the TypeError).
- **Fix:** coerce to int, clamp to 1..max, kill in `finally`.

### 8. MEDIUM: the owner-run walk runs out of file descriptors on wide directories
- **Where:** `tool_walk.py:182-205`, `tool_migration.py:343-349,367-369`.
- **Defect:** the walk opens a descriptor for every subdirectory of a directory before descending. With Docker's common default soft limit of 1024, a `node_modules` with more than about 1000 packages hits EMFILE and those subtrees are "cannot be entered".
- **Effect:**
  - The sharing pass skips them.
  - The migration's `legacy-open`, `unshare_links` and `legacy-exact` skip them, and exit 1 is accepted. The tree is stamped migrated with old ACLs and planted entries left, and the tenant UID has no access to those files.
- **Verdict:** CONFIRMED (repro with RLIMIT 1024: 1500 dirs → 479 subtrees skipped). The real limit depends on the deployment.
- **Fix:** stream the walk like `workspace_fs.walk` (bounded held descriptors) and treat skips in the migration as failure.

### 9. MEDIUM: routing, tool selection, skills and docs prefetch use the conversation's first user message
- **Where:** `consumer/_conversation.py:458-466,689,803-806`, `_conversation_prompt_builder.py:146`.
- **Defect:** Go sends the full history with the newest message last. The worker takes `next(... role == "user")`, which is the first message.
- **Scenario:** turn 1 "hi", turn 5 "refactor X and run tests" → model complexity, tool set, skills and the docs query are all decided by "hi" (this compounds #2). Auto-agent fix turns are routed by the original feature prompt.
- **Verdict:** CONFIRMED (trace).
- **Fix:** use the last user message.

### 10. MEDIUM: the docs prefetch calls an MCP tool with no policy decision
- **Where:** `consumer/_conversation.py:171-221,456`.
- **Defect:** `search_docs` is called directly on `workbench._tools`, with the user's message. There is no `request_tool_call`, mode `denied_tools` are ignored, and supervised or ask-all presets are bypassed.
- **Verdict:** CONFIRMED (trace).
- **Fix:** request a decision first (or drop the prefetch), and only use tools left in the registry.

### 11. MEDIUM: an inbound A2A task never returns its answer

- **Defect:** `A2ATaskCompleteMessage` has no output field, so `result.output` is dropped. Remote callers get "completed" with no artifact.
- **Verdict:** CONFIRMED (trace).
- **Fix:** add output or artifacts on both sides, plus a contract test.

### 12. MEDIUM (dev-only): agent-type benchmarks always fail
- **Where:** `consumer/_benchmark_runners.py:79`.
- **Defect:** `BenchmarkRuntime.publish_trajectory_event(self, **kwargs)`, but the loop passes a dict positionally. That raises TypeError on the first LLM reply, and every task scores on `ERROR: ...`.
- **Verdict:** CONFIRMED (repro).
- **Fix:** `async def publish_trajectory_event(self, event: dict) -> None`.

### 13. LOW: the worker calls the Core HTTP API without the internal key
- **Where:** `consumer/_compact.py:75-92,121-133`, `tools/search_conversations.py:58-67`.
- **Defect:** with auth on (the default) both calls get 401. Compaction logs "no messages" and publishes nothing. An LLM failure is published as a "completed" summary. Go's `HandleCompactComplete` only logs, so compaction does nothing end to end.
- **Verdict:** CONFIRMED (trace).
- **Fix:** send `X-API-Key` plus the tenant, publish a failed status, and wire the summary in Go.

### 14. LOW: tool-call results have no size bound
- **Where:** `runtime.py:490`, `tools/write_file.py`.
- **Defect:** the write_file diff carries the whole old and new file (files can be up to 10 MiB), but NATS allows 1 MiB.
- **Effect:** the publish raises MaxPayloadError and the turn fails as "internal worker error" after the file was written. A transient publish error also kills the run.
- **Verdict:** PLAUSIBLE (KI-136 covers only the conversation completion).
- **Fix:** bound the diff, wrap the publish in try/except.

### 15. LOW: a wall-clock timeout throws away the turn's record
- **Where:** `consumer/_conversation.py:490`.
- **Defect:** `AgentLoopResult(output=…, tool_calls=…, cost=…)` names fields that do not exist; pydantic ignores them. The completion of a timed-out turn carries no tool messages, cost or tokens.
- **Verdict:** CONFIRMED (trace).
- **Fix:** have the loop observe the deadline and return its state.

### 16. LOW: benchmark requests silently dropped when the worker's APP_ENV differs
- **Where:** `consumer/_benchmark.py:400-404`.
- **Defect:** a worker without `APP_ENV=development` acks the request without publishing a failed result. The run stays "running" until the watchdog ends it.
- **Verdict:** CONFIRMED (trace).

### 17. LOW: glob_files ignores the `path` argument that the policy checks

### 18. LOW: CLI backend timeout is per line, not total
- **Where:** `backends/_cli_base.py:172-181`.
- **Defect:** the timeout applies to each `readline`. A backend that keeps printing never times out, and heartbeats keep it alive.

### 19. LOW: prompt-evolution reflect is not idempotent
- **Where:** `consumer/_prompt_evolution.py`.
- **Defect:** if the final publish fails, the retry re-runs the LLM and publishes the mutation again with a fresh random `Nats-Msg-Id`, so Go gets duplicate variants.
