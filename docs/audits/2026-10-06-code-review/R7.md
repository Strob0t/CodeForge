=== FINDINGS (most severe first) ===

1. MEDIUM — security / fail-open — internal/domain/trust/trust.go:71 (MeetsMinimum) + internal/config/loader.go:337 (no validation of min_trust_bypass).
Defect: Rank() returns -1 for an unknown trust Level, and MeetsMinimum is `Rank(have) >= Rank(min)`. When the *minimum* is unknown, every level (rank 0..3) satisfies it, so the gate fails open. `quarantine.min_trust_bypass` is a free string with no validation (only expiry_hours is validated, loader.go:526), and there is no IsValidLevel in the trust package.
Scenario: operator sets CODEFORGE_QUARANTINE_MIN_TRUST_BYPASS=Verified (wrong case) or any typo → quarantine.go:69 `ann.MeetsMinimum(trust.Level("Verified"))` is true for every annotated message → quarantine is silently disabled for all inbound A2A/handoff messages. Same root cause in policy evaluation.go:170: a custom profile with a misspelled `trust_minimum` (PermissionRule.Validate does not check it either) makes any trust annotation, even untrusted, satisfy the allow rule.
Evidence (my test): untrusted annotation "meets" min="" → true, min="Verified" → true, min="high" → true, min="verified" → false.
Verdict: CONFIRMED (code trace + runnable test).
Fix: add trust.IsValidLevel; reject an unknown min_trust_bypass at startup and an unknown rule.TrustMinimum in PermissionRule.Validate; make Rank of an unknown *minimum* fail closed (treat as highest / reject).

2. MEDIUM — correctness / state machine + dead cross-language counterpart — a2a.task.cancel.
Defect: A2A task cancel is a no-op and the running task then regresses the Canceled state. internal/service/a2a.go CancelTask / internal/adapter/a2a/executor.go:234 set State=Canceled and publish a2a.task.cancel, but the worker's _handle_a2a_task_cancel (workers/codeforge/consumer/_a2a.py:97) only acks ("Future: look up the running task") and executor.execute_a2a_task (workers/codeforge/executor.py:88) is a single LLM completion with no cancellation check. The in-flight _handle_a2a_task_created then publishes a2a.task.complete (working, then completed/failed) and Go HandleTaskComplete (a2a.go:474) sets `dt.State = TaskState(state)` with no terminal/validity guard, overwriting canceled→completed.
Scenario: user POSTs /a2a/tasks/{id}/cancel → task shows "canceled" briefly, keeps running, finishes, ends up "completed". Cancel is ineffective and the state lies.
Verdict: CONFIRMED (traced end to end).
Fix: have the worker's cancel handler actually stop the task (route through NotificationHub / is_cancelled like runs/tasks do), and guard HandleTaskComplete so a terminal state (canceled/failed/completed) is not overwritten; also reject invalid state strings.

3. MEDIUM — feature gap / unenforced control (dead code) — internal/domain/branchprotection/evaluate.go + internal/service/branchprotection.go.
Defect: EvaluatePush/EvaluateMerge/EvaluateDelete and the service wrappers CheckBranch/CheckMerge have no production caller anywhere (grep of the whole repo: only *_test.go reference them; EvaluateDelete is never called at all). Rules are created/listed/deleted via REST + DB and stored, but never evaluated on any agent push, merge, delete, or delivery path (runtime_delivery/delivery have no "protect" reference).
Scenario: a user configures a rule "no force-push to main / require tests before merge"; an agent run delivers via branch/pr and pushes to main with force — nothing consults the rules. The protection is cosmetic.
Verdict: CONFIRMED (no caller outside the domain/service package and its tests).
Fix: call CheckBranch/CheckMerge (and add a delete check) from the delivery/git-push path and refuse on a deny verdict, or document the feature as not yet enforced.

4. LOW — contract drift (latent) — workers/codeforge/nats_subjects.py:10 STREAM_SUBJECTS.
Defect: STREAM_SUBJECTS lists 16 prefixes but omits "workspace.>", which Go's streamConfig (internal/adapter/nats/nats.go:139) includes. Currently harmless because the worker never creates the stream (Go does) and only uses STREAM_SUBJECTS[0] for find_stream_name_by_subject; but any future use of the list (fallback stream creation, a test) would silently drop the workspace.delete subjects.
Verdict: CONFIRMED (harmless today).
Fix: add "workspace.>" to keep the two lists identical, or derive one from the other.
