## R10b review: frontend features (dev, knowledge*, legal, llm, mcp, microagents, modes, notifications, onboarding, project, prompts, quarantine, routing, scopes, search, settings, NotFoundPage), snapshot 71bdf542

I found 22 defects. None is critical and none is a working XSS. Each one names its file (paths relative to the snapshot, frontend paths under `frontend/src/features/`), the defect, the evidence, a verdict and a fix.

### Medium

**1. Custom modes are global, kept only in memory, and any editor can overwrite them** (security / data loss; backend behind ModesPage) — CONFIRMED
- **Where:** `internal/service/mode.go:49-60,78-94`, `handlers_orchestration.go:253-288`, `cmd/codeforge/main.go:433-455`
- **Defect:** the mode map has no tenant and is never persisted. `Register` overwrites any mode that is not built in.
- **Failure:**
  - Modes created in the UI disappear when the Core restarts, which also hits single-user installs.
  - An editor in tenant B can `POST /modes {"id":"<A's mode>"}` and change A's `tools`, `denied_tools` or `prompt_prefix`. Create silently upserts; it does not answer 409.
- **Evidence:** `s.modes[m.ID] = *m`; the only persistence is the `.codeforge/modes/*.yaml` loader at startup.
- **Fix:** a tenant-scoped table; create answers 409 on an existing ID.

**2. Editing an MCP server that has no description crashes Save and Test** (correctness) — CONFIRMED by a vitest repro
- **Where:** `mcp/MCPServersPage.tsx:200,202,204` and `:239`
- **Defect:** Go omits empty `description`, `command` and `url` (`omitempty`). `handleEdit` copies `undefined` into the store, and `buildRequest` then calls `state.desc.trim()`.
- **Failure:** every server created without a description (the default) cannot be updated or tested. The error banner shows "Cannot read properties of undefined (reading 'trim')". Switching an edited sse server to stdio (or the reverse) crashes the render through `formEndpoint`.
- **Evidence:** repro `review-notes/R10b/ws/frontend/src/features/mcp/R10bRepro.test.tsx`: `updateServer calls: 0`, snippet "Cannot read properties of undefined (reading 'trim')". The existing tests use `description: ""`, which Go never sends.
- **Fix:** `desc: server.description ?? ""`, and the same for `command` and `url`.

**3. Quarantine reviewers see the payload as base64** (correctness / security UX) — CONFIRMED
- **Where:** `internal/domain/quarantine/quarantine.go:37`, `quarantine/QuarantinePage.tsx:370,476`
- **Defect:** `Payload []byte` is marshalled by `encoding/json` as base64. `formatPayload` tries `JSON.parse` on it, fails, and shows the raw base64.
- **Failure:** an admin approves or rejects a suspicious A2A message without being able to read it.
- **Fix:** decode with `atob` (UTF-8) in the UI, or send `json.RawMessage` or a string from Go.

**4. An admin can disable or delete their own account; the disable toggle has no confirmation** (single-user lockout) — CONFIRMED
- **Where:** `settings/UsersSection.tsx:40,71`, `internal/service/auth.go:236-282`
- **Defect:** the "Enabled" badge on the admin's own row is a one-click toggle. Neither the UI nor `UpdateUser`/`DeleteUser` refuses acting on yourself or on the last admin.
- **Failure:** one misclick ends all sessions and deletes the refresh tokens. A single-admin install is locked out. `syncAdminPassword` does not re-enable the account, and `BootstrapAdmin` only runs when there are no users. This is broader than KI-145, which covers only `/me/data`.
- **Fix:** hide or disable the actions on your own row; the backend answers 409 for the last enabled admin; add a confirmation dialog.

**5. Rejecting a goal proposal keeps the goal; approve and reject messages are lost while the run is active** (correctness) — CONFIRMED
- **Where:** `project/ChatMessages.tsx:211-212`, `project/ChatPanel.tsx:214-226`, `project/GoalProposalCard.tsx:39-50`, `internal/service/runtime_subscribers.go:249-256`
- **Defect:** the Core already saved the goal (`action == "create"`). "Reject" only posts the chat text "[Goal rejected: X]".
- **Failure:**
  - The rejected goal stays enabled and is injected into agent context.
  - The cards appear during the run, so the message gets 409 (one active run per conversation). `sendChatMessage` swallows the error while the card already shows approved or rejected.
  - Update and delete proposals are never applied.
- **Fix:** Reject deletes or disables the goal by its ID; buttons report errors; decisions are not sent as chat turns.

**6. Backend role gaps behind these pages** (authz; backend, flagged here because the UI exposes the actions) — CONFIRMED (`routes.go`)
- **Where:** `internal/adapter/http/routes.go:553-560,583-594,689-692,721-722,438-443`
- **Defect:** viewers can create, update and delete microagents and skills (text injected into the tenant's agent prompts). They can also create and delete the tenant's VCS accounts, add projects to scopes, attach knowledge bases, post routing outcomes (which steer model routing), and start LSP servers.
- **Fix:** `RequireRole(admin, editor)` on the mutating routes.

### Low to medium

**7. Conversation rewind always fails, and the Timeline is fed by unrelated plan steps** — CONFIRMED
- **Where:** `project/ChatHeader.tsx:130`, `project/ChatPanel.tsx:481`, `internal/adapter/http/handlers_session.go:266-276`, `useChatAGUI.ts:244-262`
- **Defect:** the UI sends no `run_id`, and the handler ignores the conversation ID, so `GetRun(ctx, "")` errors and the user gets "Rewind failed" every time. `docs/features/05-chat-enhancements.md:75-77` claims a checkpoint rewind.
- **Defect:** `stepHistory` only ever holds orchestrator plan-step events (`orchestrator_consensus.go:119`). They are not filtered by run, so steps of any plan in the tenant show up in every chat's Timeline.
- **Fix:** resolve the conversation's run on the server; filter step events by the active conversation.

**8. Trajectory export always answers 401** — CONFIRMED
- **Where:** `project/TrajectoryPanel.tsx:291`
- **Defect:** `window.open(exportUrl)` sends no `Authorization` header, and `middleware/auth.go` accepts only a Bearer token or `X-API-Key` (no cookie).
- **Fix:** fetch with the API client and download a blob, as `PrivacySection` does. The benchmark export links in another area have the same root cause.

**9. Chat state carries over to another conversation** — CONFIRMED
- **Where:** `project/useChatAGUI.ts:348-357`
- **Defect:** switching conversations resets only permissions and streamed text. `agentRunning`, `toolCalls`, `planSteps`, proposals and `runError` carry over. A's `run_finished` is then ignored because A is no longer active.
- **Failure:** after switching from running A to idle B, B shows A's tool calls, the "thinking" state and a Stop button until reload. Fork and Rewind are hidden.
- **Fix:** reset every per-run signal in the `on(activeConversation)` effect.

**10. Live output grows without bound and copies its whole list per line** (memory / performance) — CONFIRMED
- **Where:** `project/useProjectDetail.ts:166-190`, `project/LiveOutput.tsx:69`
- **Defect:** every `task.output` line copies the whole array (O(n²)). LiveOutput renders all lines with `aria-live` and no cap, and lines from different tasks are mixed under the last task ID.
- **Failure:** a verbose run freezes the project page.
- **Fix:** a ring buffer of about 1–2k lines, cleared per task.

**11. Chat attach and file upload overwrite workspace files and corrupt binaries** — CONFIRMED
- **Where:** `project/ChatPanel.tsx:132,146`, `project/FilePanel.tsx:250,260,416`
- **Defect:** attaching `package.json` in chat overwrites the repository's root `package.json` without asking (`FileService.WriteFile` overwrites). `readAsText` turns binaries into U+FFFD text.
- **Fix:** check for an existing file and confirm; refuse non-text files, or upload bytes.

**12. Edits typed during a save are marked as saved** — CONFIRMED
- **Where:** `project/FilePanel.tsx:324` (dead duplicate in `useFilePanel.ts:106`)
- **Defect:** after the write, `originalContent: t.content` takes the latest content, not what was written.
- **Failure:** characters typed while the save is in flight show as saved but were never written; closing the tab loses them.
- **Fix:** set `originalContent` to the saved `tab.content` and recompute `modified`.

**13. The file tree never refreshes after create, delete, rename or upload** — CONFIRMED
- **Where:** `project/FilePanel.tsx:613,674`
- **Defect:** `onRefetchReady` (`FileTree.tsx:308`) is never passed, and the cached full tree is invalidated only on create.
- **Failure:** deleted files stay in the tree and new files do not appear; clicking a deleted file shows an error.
- **Fix:** wire the refetch and invalidate the cache after every mutation.

**14. VCS account provider dropdown has a random default and invalid options** — CONFIRMED
- **Where:** `settings/VCSSection.tsx:69-74,150`
- **Defect:** the options come from `gitprovider.Available()`, which is in Go map order and includes `local`, `svn` and `github-api`. `Create` always rejects those three. `bitbucket` is missing.
- **Failure:** the default is `providers[0]`, so it is random per load; adding an account fails about half the time with a generic toast that hides the reason, or the token is saved under the wrong provider.
- **Fix:** a static list matching `validProviders`, and show the server's error.

**15. Chat errors are swallowed ("handled by API layer" is false; `core.ts` never toasts)** — CONFIRMED
- **Where:** `project/ChatPanel.tsx:193,223,316,532`
- **Defect:** failures of auto-creating a conversation, goal approvals, Stop and the canvas send are all silent.
- **Failure:** the canvas send clears the input before sending, so a 409 loses the user's text and sketch.
- **Fix:** toast the error and restore the input.

**16. A failed approval shows "Denied", and Allow-Always still saves its rule** — CONFIRMED
- **Where:** `project/PermissionRequestCard.tsx:57,64`
- **Defect:** any error (network or 5xx) sets the card to "deny" although the call is still pending in the Core. `handleAllowAlways` then persists the rule anyway because `handleDecision` never throws.
- **Fix:** show the error, keep the card actionable, and add the rule only after a successful approval.
